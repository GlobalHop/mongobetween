mongobetween: replica-set connection-pool proxy

This page lists every change on branch feature/rs-connection-pool and why it was made. The changes make mongobetween work as a real connection-pool proxy between PHP (ext-mongodb / libmongoc) and an unsharded MongoDB Atlas replica set. It is written for engineers and for AI agents that continue this work, so it gives context, invariants and pointers, not only a list.

1. Summary

Starting point. Upstream mongobetween was designed to sit in front of mongos routers of a sharded cluster. A test about a year earlier, with PHP against an unsharded Atlas replica set, failed. Upstream has had almost no maintenance since 2024. Its own README says direct replica-set use "hasn't been battle tested".

Result. The branch keeps the core design: the proxy impersonates a mongos and forwards wire messages byte for byte through a Go driver connection pool. It fixes or adds everything that design needs to work for PHP against a replica set:

  • Correct handshake: hello and isMaster are answered locally, in the request's opcode, with the real upstream wire version.
  • MongoDB error replies with retry labels instead of closed sockets, so libmongoc retries during failovers.
  • Client read preference honoured (mode, tags, maxStalenessSeconds). Writes always go to the primary.
  • Cursor and transaction pinning bugs fixed.
  • Optional inbound TLS / mTLS and SCRAM-SHA-256 proxy users that are separate from the Atlas user.
  • Upstream TLS can be enforced. Pre-authentication limits, connection limits, bounded shutdown.
  • Modern Go driver (v1.17.10), patched dependencies, distroless image, Docker test harness with a replica set, PHP smoke test, new CI.

Verified on Atlas MongoDB 8.0.37 and 9.0.7 from PHP: connection, CRUD, aggregations, transactions, read preferences and error codes. Results through the proxy match a direct connection, except for two intended differences (handshake persona, code 133). Two Atlas "Test Failover" runs showed no application-visible errors apart from one lost cursor, which now gets the real code 91 instead of a generic one.

2. Background: why change anything

The analysis of upstream (see .claude/knowledge/01..06) found these problems for our setup:

Fake isMaster reply hard-codes maxWireVersion: 8Newer libmongoc requires a higher minimum wire version and refuses the server. Newer server features stay disabled.

An Atlas user who gave the app's Atlas URI (mongodb+srv, credentials, replicaSet) to PHP and pointed it at the proxy would also fail. This was the most probable cause of the earlier failed test (it matches upstream issue #30). The runbook now documents the correct PHP URI.

3. How the proxy works now

PHP appext-mongodb / libmongoc. URI mongodb://proxy:port, optional TLS and proxy user.
→
mongobetween listenerOptional TLS/mTLS. Optional SCRAM-SHA-256 against proxy users. Handshake answered locally as isdbgrid (mongos).
→
RoutingPick a server: transaction pin, then cursor pin, then client $readPreference, then primary. Writes always primary.
→
Go driver v1.17.10 poolOne checkout per message. Raw bytes forwarded. TLS + SCRAM to Atlas with the Atlas user.
→
Atlas replica setThe app never sees member hostnames. SDAM and failover happen inside the Go driver.
  • Persona. The proxy tells the client it is a mongos (msg: "isdbgrid"). libmongoc then sends $readPreference inside each command and accepts a single seed. That is why replicaSet= must not be in the PHP URI.
  • Wire version. The handshake reply mirrors the upstream maxWireVersion, capped at 25 because driver v1.17.10 knows no higher value. MongoDB 9.0 reports wire 29, so PHP sees 25 through the proxy. Exposing 29 needs the Go driver v2 migration.
  • Absent fields on purpose. The reply has no helloOk, topologyVersion, compression, setName, hosts or speculativeAuthenticate. This keeps clients on polling monitoring and uncompressed frames, which are the only modes the proxy supports.
  • Failures. A proxy-side failure (selection timeout, checkout timeout, pool cleared) becomes a MongoDB error document with retry labels. The client socket stays open.

4. Changes by area

Each card says what changed, why, and where to look. Commit hashes refer to this branch.

wire protocolmust-have

4.1 Handshake: intercept hello, reply in request opcode, mirror wire version

  • hello and isMaster (also legacy ismaster, also with a bool value) on admin are answered locally, in OP_MSG or OP_REPLY to match the request.
  • maxWireVersion mirrors the upstream topology, capped at 25. Flag -max-wire-version overrides it (0 = mirror; an explicit value must be 0..25 or the proxy refuses to start).
  • saslSupportedMechs is included only when inbound auth is on. logicalSessionTimeoutMinutes stays so sessions, retryable writes and transactions work.
  • Old mongo/ismaster.go replaced by mongo/handshake.go.
Why: the hard-coded wire version 8 would break any libmongoc that requires a higher minimum and hid server features. Stable API clients send hello in OP_MSG, which upstream did not intercept.

resiliencemust-have

4.2 MongoDB error replies instead of closed sockets

  • Proxy-side failures are classified by ClassifyProxyError and sent as a normal error document in the request's opcode (ErrorResponse).
  • Default: code 11602 InterruptedDueToReplStateChange. Labels depend on the request: RetryableWriteError outside a transaction, TransientTransactionError inside one, RetryableWriteError + UnknownTransactionCommitResult on commitTransaction.
  • Upstream state-change codes (91, 11600, 11602, 10107, 13435, 13436, 189) are forwarded with their real code and codeName. This includes the case where the Go driver wraps the cause in its unexported pool-cleared error; the code is parsed from that error's text.
  • Code 133 FailedToSatisfyReadPreference for a non-primary read preference that no member matches. On a stable replica set (a primary, no member in Unknown, RSMember or RSGhost state) it fails fast, as a mongos does, instead of waiting for the selection timeout.
  • Code 2 BadValue for an invalid $readPreference; code 13 when dynamic config disables writes; code 18 for auth commands when inbound auth is off.
  • Client-visible errmsg values are fixed strings prefixed mongobetween: . They never contain upstream hostnames or topology text. The full cause goes to the Proxy error reply log line and the proxy_error_reply counter.
  • -checkout-timeout (default 10s) bounds the wait for an upstream connection.
Why: a closed socket makes libmongoc treat the proxy as a dead server. A retryable error code lets it retry reads and writes once during an Atlas election, which is how a real mongos behaves. Code 133 fail-fast was added after the Atlas test showed an unsatisfiable tag set waited 30 s and leaked member hostnames. State-code forwarding was added after the Atlas failover test showed a lost cursor reported as generic 11602 while Atlas had sent 91 ShutdownInProgress.

safety

4.3 Frame limits and exhaust cursors

  • Client frames must be 16 B to 48 MB + 16 KiB. Bodies are read incrementally, so memory follows the bytes actually received.
  • A client that starts a TLS handshake on a plain-text port is detected and closed at once (log TLS client on plain-text port).
  • The exhaustAllowed flag is stripped from OP_MSG (StripExhaustAllowed). A reply with moreToCome never returns to the pool.
Why: upstream allocated whatever length a frame header claimed (up to about 2 GB) and panicked on negative lengths. Exhaust streams leave a connection in a state the pool cannot reuse.
Commits b22b29d, c88e3e1 · Files mongo/exhaust.go, proxy/connection.go, proxy/limits_test.go
routing

4.4 Cursor and transaction pinning

  • Cursor pins are keyed by cursor id and full namespace, the same on store and lookup. killCursors evicts the pin.
  • A transaction pin is used only for the transaction that created it. A new transaction (startTransaction) never reuses a stale pin. Pin precedence lives in pinnedServer.
Why: cursor ids are unique per server, not globally. After an Atlas election, a reused transaction pin would send the new transaction to the former primary.
Commits 6f0b37d, 930de3a, 61e4e29, c37b237 · Files mongo/cursor_cache.go, mongo/pinning.go, mongo/mongo.go

4.5 Client read preference

  • Base taken from the crowdsecurity fork's readpref branch (commit 7272f94, author kept). It extracts $readPreference from wire messages and builds a selector.
  • Extended to tags and maxStalenessSeconds. Default is primary when absent, not a document, or unknown mode.
  • A present but invalid read preference gets code 2 BadValue.
  • Write commands (IsWrite) always select the primary, whatever $readPreference they carry, as a real mongos does.
Why: to allow secondary and analytics-node offload. libmongoc sends $readPreference to a mongos, so the proxy must act on it or it is silently ignored. Reusing an existing fork avoided writing the parser from zero.

operations

4.6 Shutdown, cancellation and upstream TLS enforcement

  • -shutdown-timeout (default 30s): on SIGTERM/SIGINT the proxy stops accepting, waits for clients, then force closes them and aborts their in-flight upstream requests (Mongo.CancelInFlight).
  • A second signal does the same at once, then exits with status 1 after 2 s if still running.
  • -require-upstream-tls: refuse to start unless every upstream URI uses TLS with certificate verification. tlsInsecure=true is rejected.
  • Upstream clients are closed on exit.
Why: PHP persistent connections never close by themselves, so upstream shutdown hung until SIGKILL. TLS to Atlas is a hard requirement; the flag guards against a mistyped URI.

securityoptional

4.8 Inbound SCRAM-SHA-256 with proxy-only users, and pre-auth hardening

  • -auth-users-file: one user:password per line. These users exist only in the proxy and must differ from the Atlas user. Server side of SCRAM uses xdg-go/scram.
  • Unknown users get decoy credentials, so a client cannot tell a wrong user from a wrong password.
  • The salt is sent as 28 raw bytes. A base64 salt worked with the Go driver but libmongoc rejected it (found on Atlas test).
  • Before authentication only the handshake, saslStart/saslContinue, ping, buildInfo and endSessions are allowed; everything else gets code 13. No client bytes are forwarded before auth: ping/endSessions/logout are answered locally, buildInfo uses a body the proxy builds.
  • Unauthenticated frames are capped at 64 KiB. -auth-timeout (30s) closes an idle unauthenticated connection; the timer restarts per message so monitoring connections survive.
  • -max-connections caps open client connections per listener (counter connection_rejected).
  • Pre-auth requests are tagged command:unauthenticated in statsd so clients cannot create tag values.
  • SCRAM input is validated; a short proof no longer panics.
Why: upstream had no inbound auth (maintainers suggested network isolation), so anyone reaching the port had the Atlas user's rights. The user required local credentials that do not match Atlas. Forwarding pre-auth bytes would let an unauthenticated client use the upstream connection.

4.11 Driver, Go version, image and dependencies

  • go.mongodb.org/mongo-driver v1.14.0 → v1.17.10 (last v1). Supports Atlas 8.0+.
  • go directive 1.18 → 1.26.0 (required by upgraded dependencies). Build image golang:1.27, CI Go 1.27.
  • Runtime image scratch → gcr.io/distroless/static-debian12:nonroot (non-root, has /tmp, CA certificates). Static, trimmed build. .dockerignore added.
  • go-getter → 1.8.10, golang.org/x/crypto → 0.59, grpc → 1.85, yaml.v3 → 3.0.1 and other transitive upgrades, to clear known CVEs.
  • xdg-go/scram is now a direct dependency (inbound auth).
Why: driver v1.14 does not officially support Atlas 8.0. Security scanners reported several critical CVEs in go-getter and x/crypto. The old image ran as root and had no /tmp, so -dynamic failed.

Do not bump the driver casually. TestDriverVersionPinned in mongo/errors_test.go fails if the driver version changes, because state-code forwarding parses the text of the driver's pool-cleared error (the type is unexported and has no Unwrap). On a bump, re-check the format string in the driver's x/mongo/driver/topology/pool.go.

7. PHP client URI rules

PHP must connect to the proxy with mongodb://<proxy-host>:<port>, not with the Atlas URI.

Allowed

  • Proxy user and password (only with -auth-users-file)
  • tls=true + tlsCAFile (only with listener TLS)
  • readPreference, tags, maxStalenessSeconds
  • retryWrites, retryReads, sessions, transactions
  • serverApi

Do not use

  • mongodb+srv://
  • replicaSet= (libmongoc drops a mongos from an RS topology)
  • loadBalanced=true
  • Atlas credentials
  • tls=true on a plain listener

From another Docker container, use the proxy container's name or network alias, not localhost. The local test setup attaches the proxy container to the shared Docker network with alias mongobetween, so apps use mongodb://mongobetween:27012.

9. Known limitations and open items

  • Go driver v2 migration not done. Needed to report wire versions above 25 (MongoDB 9.0 = 29). Requires re-checking the pool-cleared error parsing.
  • Inbound auth is SCRAM-SHA-256 only. All proxy users share the Atlas user's privileges (no per-user rights).
  • No speculativeAuthenticate (one extra round trip per new client connection).
  • No idle/read deadline on authenticated client sockets.
  • Exhaust cursors and OP_COMPRESSED unsupported by design.
  • IsWrite completeness for DisableWrites, legacy OP_UPDATE/OP_DELETE bugs, replacing go-getter: not done.
  • Sharded persona not tested by the new harness.
  • Rare shutdown race: a request arriving just after Kill may hang until SIGKILL; the second signal covers it.
  • Open decisions: G115 per-site #nosec instead of a global exclude.

The full raw list of deferred minor findings is in .claude/knowledge/08-open-follow-ups.md.

10. Notes for AI agents

Read this before changing the code.

Where to start

  • .claude/knowledge/README.md then 05-sharded-vs-unsharded.md and 07-change-backlog.md. Files 01–04 and 06 describe upstream before this branch unless marked.
  • docs/atlas-poc.md for operational behaviour and the error table.
  • Request path: proxy/connection.go (read, auth gate, dispatch) → mongo/command.go / mongo/operations.go (decode) → mongo/mongo.go RoundTrip (select, pin, checkout, forward) → mongo/errors.go (error replies).

Invariants that must hold

  • The handshake reply must not contain helloOk, topologyVersion, compression, setName, hosts or speculativeAuthenticate. Adding any of them switches clients to modes the proxy cannot handle.
  • Reported maxWireVersion must not exceed what the bundled driver supports (topology.SupportedWireVersions.Max).
  • Never send a reply with moreToCome back to the pool; keep stripping exhaustAllowed.
  • Client-visible error messages are fixed strings. Never put err.Error(), hostnames or topology text in a client reply; log them instead.
  • Before authentication, never forward client bytes upstream.
  • Write commands always go to the primary.
  • Cursor pin store and lookup must use the same (id, namespace) key.
  • TestDriverVersionPinned guards the driver version; see 4.11.

Testing rules

  • Run tests with make test-docker (needs Docker, e.g. Rancher Desktop). Clean up with make test-docker-down. make test-unit runs without a database.
  • Never point tests at a MongoDB on the host's 27017; the developer machine may run a real one.
  • For Atlas tests, use separate prefixed collections and drop them afterwards; do not rely on dropDatabase.

Secrets

  • Never put a real connection string, password or token in code, commits, logs, docs or command lines. Pass the Atlas URI through an environment variable ('${MONGO_URI}', single quoted, expanded by the proxy) or a 0600 env file.
  • The proxy users file holds clear-text passwords: mount it as a secret, mode 0600.

Useful commands

make build            # bin/mongobetween
make test-docker      # full suite with -race in Docker
make test-unit        # no database
make php-smoke        # PHP ext-mongodb checks through the proxy
make lint             # golangci-lint v2
docker build -t mongobetween:dev .

# run against Atlas (URI in env, never in argv)
mongobetween -require-upstream-tls -ping '127.0.0.1:27016=${MONGO_URI}'
